📋 PROJECT OVERVIEW
───────────────────────────────────────────────────────────────────────────────
SmartPharm is a comprehensive inventory management system for pharmacy shops with:
  • Offline-first capability with automatic sync when online
  • AI integration for medicine scanning and recommendations
  • Patient and loan management with payment tracking
  • Expiry notifications and inventory alerts
  • Multi-user support with role-based access control

TECH STACK: MERN (MongoDB, Express.js, React.js, Node.js) + IndexedDB + LocalStorage


╔═══════════════════════════════════════════════════════════════════════════════╗
║                            PART 1: KEY FEATURES                              ║
╚═══════════════════════════════════════════════════════════════════════════════╝

1. 💊 INVENTORY MANAGEMENT
   - Store medicines/products with detailed dosage information
   - Track price history with updates and breakdowns
   - Monitor stock levels and trigger low-stock alerts
   - Support multiple units (sachet, box, bottle, capsule, etc.)

2. 📄 INVOICE MANAGEMENT
   - Create purchasing & selling invoices
   - Add/remove items dynamically with price adjustments
   - Mark invoices as completed with timestamps
   - Track customer details and payment status

3. 💰 LOAN TRACKING
   - Record loans to patients with product lists and amounts
   - Payment breakdown tracking with multiple payment channels
   - Mark partial or full payments with automatic balance calculation
   - Payment notifications for overdue loans

4. 👥 PATIENT MANAGEMENT
   - Store recurring patient profiles with medical history
   - Track dosage schedules and mark completion status
   - Record health metrics (BP, weight, sugar level, pregnancy status)
   - Resolution tracking with snapshot data on patient recovery

5. ⏰ EXPIRY MANAGEMENT
   - Automatic notifications for products expiring within 1 year
   - Color-coded expiry status (green/yellow/red)
   - Re-notification system for unresolved expiry items
   - Historical expiry tracking

6. 🤖 AI INTEGRATION
   - Medicine image scanning for product identification
   - Dosage suggestions based on patient conditions
   - Automated recommendations (best sellers, similar medicines)
   - Description generation from product names and characteristics

7. 📊 ANALYTICS & INSIGHTS
   - Dashboard with recent activity (5 latest events)
   - Statistics aggregation (total patients, loans, revenue)
   - Smart suggestions (overdue loans, expiring products, volatile prices)
   - Seasonal trend analysis from historical data

8. 🔌 OFFLINE-FIRST ARCHITECTURE
   - Complete offline functionality with IndexedDB
   - Automatic sync queue when connection restored
   - Local image storage with media manager
   - Configuration caching in LocalStorage

9. 📤 IMPORT/EXPORT
   - Export shop data as JSON backup
   - Import data with conflict resolution
   - Bulk product/patient data import

═══ GENERAL FIELDS (Applied to All Core Models) ═══════════════════════════════

All data models include these base fields:
  • _id: ObjectId (MongoDB unique identifier)
  • userId: ObjectId (reference to User - multi-tenant support)
  • createdAt: Date (auto-generated on creation)
  • updatedAt: Date (auto-updated on modification)
  • createdBy: ObjectId (reference to User who created)
  • description: String (optional notes/details)
  • syncInfo: {
      dataUploaded: Boolean (synced to server),
      mediaUploaded: Boolean (images synced)
    }


═══ PRODUCT / MEDICINE SCHEMA ══════════════════════════════════════════════════

Stores all medicine and product information.

{
  name: String (required, unique per user),
  
  type: Enum(injection, syrup, drop, cream, inhaler, tablet, capsule, 
              ointment, powder, solution, spray, item),
  
  dosage: {
    pregnantAllowed: Boolean (can pregnant women use),
    sensitive: Boolean (requires caution/prescription),
    breakdown: [{
      label: String (e.g., "Adult", "Child 6-12", "Infant"),
      description: String (e.g., "2ml three times daily"),
      ageRange: String (e.g., "12+", "6-12", "0-5")
    }]
  },
  
  pricing: [{
    unit: Enum(sachet, capsule, box, bottle, ampule, ointment, ml, pack),
    amount: Number,  // Price in Naira
    quantity: Number (e.g., 10 sachets per box)
  }],
  
  stock: Number (current inventory count),
  
  expiryDate: Date (optional),
  
  relatedProducts: [ObjectId] (references to similar/complementary medicines),
  
  priceHistory: [{
    date: Date,
    price: Number,
    unit: String
  }],
  
  invoiceCount: Number (default: 0, times sold),
  
  mediaSource: String (optional - URL or localMedia:id.png)
}


═══ PATIENT SCHEMA ═════════════════════════════════════════════════════════════

Tracks recurring patients and their medical history.

{
  name: String (required),
  phone: String (optional),
  gender: Enum(male, female, other),
  
  age: Enum(infant, child, teenager, adult, senior),
  
  condition: String (optional - reason for visit, e.g., "malaria", "fever"),
  
  healthData: {
    weight: Number (kg),
    bloodPressure: String (e.g., "120/80"),
    isPregnant: Boolean,
    sugarLevel: Number (mg/dL),
    isInfectious: Boolean,
    diabetesLevel: String (optional)
  },
  
  location: String (optional - address),
  
  returningCount: Number (default: 0, tracks visit frequency),
  
  dosageSchedule: [{
    label: String (e.g., "PCM 500mg"),
    prescribedDate: Date,
    completed: Boolean,
    completedDate: Date
  }],
  
  resolutionHistory: [{
    date: Date,
    status: String (e.g., "Recovered", "Improved", "On Treatment"),
    snapshot: Object (health metrics captured at this point)
  }],
  
  totalLoans: Number (reference count),
  
  totalLoanAmount: Number (sum of all loan amounts),
  
  isResolved: Boolean (default: false, marks treatment completion),
  
  notes: String (treatment notes and observations)
}


═══ LOAN SCHEMA ════════════════════════════════════════════════════════════════

Manages credit given to patients with payment tracking.

{
  borrowerName: String (required),
  borrowerPhone: String (required),
  borrowerGender: Enum(male, female),
  borrowerLocation: String (optional),
  
  loanItems: [{
    productId: ObjectId (ref: Product, optional),
    productName: String,
    quantity: Number,
    unitPrice: Number,
    totalPrice: Number,
    description: String,
    date: Date (default: Date.now())
  }],
  
  amountSummary: {
    totalLoanAmount: Number (sum of all items),
    totalPaid: Number (amount received so far),
    balanceRemaining: Number (auto-calculated: total - paid)
  },
  
  paymentHistory: [{
    date: Date,
    amountPaid: Number,
    paymentMethod: Enum(cash, bank_transfer, mobile_money, cheque),
    paidBy: String (person who made payment),
    itemsCovered: [String] (item IDs or descriptions),
    notes: String
  }],
  
  loanStatus: Enum(active, partial_paid, fully_paid, overdue),
  
  isOverdue: Boolean (auto-set if balance > 0 and > 30 days old),
  
  notes: String (special notes or agreements)
}


═══ INVOICE SCHEMA ═════════════════════════════════════════════════════════════

Records all buying/selling transactions.

{
  invoiceNumber: String (unique, auto-generated: INV-YYYY-MM-DD-XXXX),
  
  type: Enum(purchasing, selling),
  
  items: [{
    productId: ObjectId (ref: Product, optional),
    productName: String (required),
    quantity: Number (required),
    unitPrice: Number (required),
    totalPrice: Number (quantity * unitPrice)
  }],
  
  totalAmount: Number (sum of all items),
  
  customerDetails: {
    name: String (optional, for selling invoices),
    contactPhone: String (optional),
    paymentAmount: Number (amount customer paid),
    remainingBalance: Number (auto-calculated),
    paymentDate: Date
  },
  
  isCompleted: Boolean (default: false),
  completedDate: Date,
  
  invoiceDate: Date (default: Date.now()),
  
  notes: String (optional memo/terms)
}

🔐 AUTH PAGES (Login/Register)
───────────────────────────────────────────────────────────────────────────────
DESCRIPTION:
  Entry point for the application with account authentication. Includes login/
  registration with email verification and session management.

FEATURES:
  ✓ Registration with email, phone, shop info, address
  ✓ Login with email/phone and password
  ✓ Email verification before account activation
  ✓ Session timeout (auto-logout after 30 days inactivity)
  ✓ Passcode lock (4-digit PIN) on app restart
  ✓ Password reset via email

ROUTES: /auth/login, /auth/register, /auth/verify-email, /auth/forgot-password

IMPLEMENTATION DETAILS:
  Frontend:
    - React form with validation (email format, password strength)
    - Protected routes redirect to /auth/login if not authenticated
    - Store JWT token in secure httpOnly cookie + local state
    - Intercept API calls to attach auth header
    - Passcode modal on app load with sessionStorage tracking
  
  Backend:
    - Hash passwords with bcrypt (salt rounds: 10)
    - Generate JWT tokens with 30-day expiry
    - Implement refresh token mechanism for token renewal
    - Send verification email via Nodemailer with confirmation link
    - Track login attempts and lock account after 5 failed attempts
    - Verify JWT on every protected endpoint

🔄 SYNC SYSTEM & OFFLINE MODE
───────────────────────────────────────────────────────────────────────────────
DESCRIPTION:
  Core offline-first architecture with automatic sync queue and conflict
  resolution.

FEATURES:
  ✓ Offline operations: Create/update all entities locally via IndexedDB
  ✓ Sync Queue tracks:
      - Operation (POST/PATCH/DELETE)
      - Endpoint and payload
      - Callback function name
      - Timestamp and retry count
      - Status (pending, syncing, completed, failed)
  
  ✓ Auto-sync when online:
      - Check if entity exists on server (by ID)
      - If exists → PATCH (update), else POST (create)
      - Execute callback on success
      - Mark as synced in syncInfo
  
  ✓ Conflict resolution:
      - Server timestamp takes precedence
      - Show user warning with merge options
  
  ✓ Media sync:
      - Store local images as blobs in IndexedDB
      - Name: {entityType}_{entityId}_{date}.{ext}
      - Upload to Cloudinary via /api/media/upload
      - Replace local URL with cloud URL

IMPLEMENTATION DETAILS:
  Frontend:
    - Dexie.js for IndexedDB with typed tables
    - useDb hook with store/update/query methods
    - useSyncQueue hook to trigger sync
    - Service Worker for offline detection
    - Automatic sync on connection restore
  
  Backend:
    - Sync queue API endpoints
    - Validation callbacks for data integrity
    - Media upload to Cloudinary + local caching
    - Timestamp-based conflict detection
    - Retry mechanism with exponential backoff

KEY DEVELOPMENT PRACTICES

1. Code Organization:
   - Use MVC pattern: Models, Views, Controllers
   - Separate utilities, middlewares, routes, controllers
   - Keep files focused and modular
   - Use meaningful, consistent naming

2. Offline-First Architecture:
   - All data operations sync to IndexedDB first
   - Validate data before sending to server
   - Implement conflict resolution gracefully

3. State Management:
   - Use React Context for auth, user, theme
   - Use React Query for server state
   - Use local state for UI-only state

4. API Design:
   - RESTful endpoints with clear naming
   - Proper HTTP status codes
   - Validation on both frontend & backend
   - Rate limiting for public endpoints

5. Security:
   - Hash passwords with bcrypt
   - Use JWT with short expiry + refresh tokens
   - Validate all user inputs
   - HTTPS only in production
   - Store sensitive data server-side only

6. UI/UX Principles:
   - Consistent primary/secondary colors
   - Medicine-themed color palette (greens, blues, whites)
   - Dark theme with auto phone theme detection
   - Responsive design (mobile-first)
   - Accessibility (alt text, ARIA labels, etc.)

7. Performance:
   - Lazy load components & images
   - Debounce search inputs (300ms)
   - Cache API responses (30s default)
   - Minimize bundle size
   - Pre-compute heavy aggregations

8. Testing:
   - Unit tests for utilities
   - Integration tests for API endpoints
   - E2E tests for critical flows
   - Minimum 70% code coverage
